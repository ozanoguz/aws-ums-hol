# Live FortiGate traffic demo

Optional spoke VPC, EC2 HTTP dashboard, private syslog collector and read-only AWS discovery. Integrated with `examples/spk_gwlb_asg_fgt_gwlb_igw/demo.tf`; disabled unless `web_demo` is configured.

## Enable

Replace the existing lab tfvars placeholders, then add:

```hcl
web_demo = {
  allowed_client_cidrs = ["0.0.0.0/0"] # Public HTTP for browsers and the cross-account monitor
  vpc_cidr            = "10.50.0.0/16"      # Must not overlap connected VPCs
}
```

This creates an **additional demo spoke**, leaving `spk_vpc` entries unchanged. Includes workload/endpoint subnets in the first AZ, GWLB endpoint, symmetric Internet inspection routes, EC2/EIP and private telemetry peering. Supports this example's **two-arm, root-VDOM** topology in one account/region. ASG names, target group and endpoint service are derived from module outputs.

For existing management route tables, supply their IDs explicitly:

```hcl
web_demo = {
  allowed_client_cidrs = ["0.0.0.0/0"]
  management_route_tables = { az1 = "rtb-REPLACE", az2 = "rtb-REPLACE" }
}
```

Otherwise the example derives them from its `fgt_login` route tables. Each management subnet needs a route. No ASG capacity settings are changed. Allow three instances in FortiManager when demonstrating scale-out. For UMS, set the existing lab's legacy `enable_fgt_system_autoscale` flag to **false**, retaining `fmg_integration.ums`; the legacy Lambda scale-in role handling can otherwise conflict with UMS.

From the example directory in your AWS session:

```sh
terraform init
terraform plan -out=demo.plan
terraform apply demo.plan
terraform output -json web_demo
```

Review the full plan. HTTP/80 is public for browser access and cross-account monitoring; the page and its read-only API display instance/serial information without an application login. Syslog remains private. No SSH port is opened; use Systems Manager Session Manager after outbound connectivity works.

## FortiManager setup

1. Complete GENEVE provisioning and the inspection policy package. Permit the demo workload's required bootstrap/SSM/AWS outbound HTTPS traffic, and HTTP from any IPv4 source. The default workload subnet is `10.50.0.0/24`.
2. On the policy inspecting demo HTTP, enable all-session logging and **Log at Session Start** for fast events. Equivalent policy settings:

   ```text
   set logtraffic all
   set logtraffic-start enable
   ```

   Edit the existing FortiManager policy package; preserve its actual ID, matching criteria and security profiles. Disable NAT for the GENEVE inspection policy so connection tuples remain correlatable.
3. Extract the generated logging template:

   ```sh
   terraform output -json web_demo | python3 -c 'import json,sys; print(json.load(sys.stdin)["fortimanager_cli_template"])'
   ```

4. Create a regular CLI provisioning template using that output. Reserve **syslogd2** and static route **190**, or select unused alternatives. Add it to your UMS Template Group and auto-onboarding rule; assign/install it to existing FortiGates as well. It leaves syslogd, credentials, central-management and UMS settings untouched.
5. Preserve management DHCP/default routing on `port2` and DHCP distance 6 on `port1`. The generated log destination is the **secondary collector IP**, normally `10.50.0.11`, not the HTTP server IP `10.50.0.10`. Management security groups/NACLs must permit outbound UDP 5514.
6. Open the public `url` from an external browser **outside the spoke VPC** and click **Start traffic**. Internal access can bypass inspection. Scale out in FortiManager and wait for discovery, healthy GWLB status, and actual observed connections.

## What the lights mean

The web server responds; FortiGates inspect. The collector matches browser test connections to FortiGate forward logs using source IP/port, destination private IP/port and time. AWS inventory alone never triggers a light. Logs require `devid`, `eventtime` (nanoseconds), `srcip`, `srcport`, `dstip`, `dstport`, `proto`, `type`, `subtype` and `action`. Keep clocks synchronized within 15 seconds. UDP can lose/delay messages; missing attribution is displayed honestly. This is a lab visualization, not audit-grade accounting.

Discovery polls every 10 seconds; new ASG members automatically get cards. Serial numbers appear after valid logs. The service closes HTTP connections so tests create new TCP flows. Leave GWLB on **5-tuple stickiness**. Distribution can be uneven; a third node must be healthy and eligible for your AZ/cross-zone settings before receiving new connections. Do not front this server with an HTTP reverse proxy or enable inspection NAT without changing the attribution method.

Only test connections generated by the page count as activity. Dashboard polling, health checks, unrelated traffic and fake events from unknown sender IPs do not light cards. Discovery uses the EC2 role; AWS/FM credentials never enter the page. Traffic history is bounded and in-memory; counters reset on restart.

## Network and bootstrap

The workload ENI has primary HTTP and secondary telemetry IPs. Its EIP maps only to the primary. VPC peering routes a collector `/32` from each management subnet; the demo subnet gets a security-VPC return route. The generated FortiManager route also points only to that secondary address. Keeping the IPs separate avoids a management route to the inspected HTTP server breaking its reverse-path checks. Linux configures the secondary address before service startup, including after reboot.

Syslog uses unauthenticated UDP exclusively on the private peering path. The receiver SG restricts sources to management subnet CIDRs; the parser also checks source IP against discovered ASG ENIs. There is no public syslog ingress.

Installing packages traverses GWLB. Before GENEVE/outbound policy provisioning, bootstrap may fail; a systemd timer retries every minute. The URL starts working once outbound access and installation succeed. Use SSM to inspect:

```sh
sudo journalctl -u gwlb-demo-install.service -u gwlb-demo.service -n 100
sudo systemctl status gwlb-demo-install.timer gwlb-demo.service
ip -4 address
```

- **Page unreachable:** check HTTP/80 ingress, endpoint acceptance, GWLB health, policies, routes and bootstrap logs.
- **AWS inventory unavailable:** check instance role, DNS/HTTPS egress and server logs. Old inventory is marked stale.
- **Cards but no lights:** check policy logging, syslogd2, peering routes, clocks and UDP 5514. Idle is not the same as unhealthy.
- **Only one node lights:** check fresh connections, 5-tuple stickiness and cross-zone eligibility. Hashing does not guarantee even distribution.
